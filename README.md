# 方言で出身地当て

方言・地域の生活知識についての質問に答えていくと、出身地(言語形成期を過ごした地域)を都道府県から県内の地域まで推定する Web ゲームです。静的サイトとして GitHub Pages で公開する予定です。

現在は試作版です。質問データと進行役の台詞は、まだ監修を受けていません(`docs/needs-review.md`)。まだ公開していません。

## 特徴

- ベイズ推定で絞り込むので、数問の誤答があっても正解に戻れます。
- 進行役のキャラクターが、その時点の最有力地域の方言で喋ります。
- 推定の途中経過を地図のヒートマップで見せます。

質問文はすべて自作です。

## 開発

Node.js 24 以上が必要です。

```
npm install
npm run dev        # 開発サーバー
npm test           # 単体テスト
npm run build      # 型チェックと本番ビルド(dist/)
npm run licenses   # LICENSES.md とクレジット画面用データを再生成
```

## 地理データ

地域の基本単位(セル)は二次医療圏です(335)。`data/geo/` の成果物はコミット済みなので、通常は作り直す必要はありません。

```
npm run geo:fetch  # 元データを data/raw/ に取得(約1.2GB、コミットしない)
npm run geo:build  # cells.json / municipalities.json / japan.topo.json を生成
```

| ファイル | 内容 |
| --- | --- |
| `data/geo/cells.json` | セルの id・名称・都道府県コード・代表点・人口、都道府県の一覧 |
| `data/geo/municipalities.json` | 市区町村とセルの対応表(人口付き) |
| `data/geo/japan.topo.json` | 簡略化した地図(レイヤー:`cells`、`prefs`) |

- 境界と二次医療圏の構成は国土数値情報 医療圏データの2020年度版、人口は令和2年国勢調査によります。2024年度からの第8次医療計画で見直された医療圏は反映していません。
- セルの代表点は、構成市区町村の重心を人口で重み付けして平均した点です(面積の重心ではなく、人が住んでいる側に寄ります)。
- 地図では 3 km² 未満の島を省略しています。人口などのデータからは省いていません。
- 簡略化の強さなどは `scripts/geo/build.ts` の `GEO_CONFIG` で変えられます。

## 推定エンジン

`src/engine/` にあります。事後確率 ∝ 事前確率(人口比)× Π P(回答 | セル) を、回答のたびに更新して正規化します。

- **誤答への耐性**:すべての尤度に下限 epsilon(初期値 0.03)を設けています。`有効な尤度 = epsilon + (1 − 選択肢数 × epsilon) × 元の尤度` で、「一定の確率で出身地と無関係に答える人がいる」というモデルに相当します。
- **次の質問**:期待情報利得(事後エントロピーの期待減少量)が最大の質問を選びます。同じカテゴリが続くと点数を割り引き、面白さの重みも加えられます。この選び方により、最初は全国を大きく分ける質問、地域が絞れてからはその地域の中で差が出るローカルな質問、という順に自然に進みます。
- **終了条件**:最上位セルの確率が 0.8 以上、25 問に到達、残りの質問の最大期待情報利得が 0.01 ビット未満、のいずれか。
- **結果の粒度**:セルの確率が十分ならセルまで、そうでなければ都道府県まで、それも足りなければ地方までを答えます。
- **戻る**:回答履歴から状態を再計算します。
- 閾値はすべて `src/engine/config.ts` で変えられます。

VRChat(UdonSharp)へ機械的に移植できるよう、エンジンは DOM・外部ライブラリ・クロージャ・高階関数・Map/Set・ジェネリクスを使わず、平たい数値配列と for ループだけで書いています。モデル JSON もオブジェクト・配列・文字列・数値だけの構造です。

## シミュレーション

```
npm run simulate                 # 実際の質問セット(data/questions/)で実行
npm run simulate -- --synthetic  # 機械的に作った仮の質問セットで実行(エンジンの動作確認用)
```

各セルから、尤度表どおりに答える仮想回答者を作り(一定確率でランダム回答を混ぜる)、推定させて正答率を出します。乱数はシード固定です。

**この数字が示すのは、エンジンの整合性と質問セットの識別力であって、実際の人間での正答率ではありません。** 仮想回答者は尤度表そのものに従って答えるためです。尤度表の数値は作成時の見積もりで、調査データから計算したものではありません。

質問データ(44問、平滑化 15 km)での結果(`npm run simulate`、各セル 20 回、シード 1、設定は初期値、人口で重み付け):

| ランダム回答率 | 地方 top-1 | 都道府県 top-1 | 都道府県 top-3 | セル top-1 | セル top-3 | 平均質問数 |
| --- | --- | --- | --- | --- | --- | --- |
| 10.0% | 88.3% | 47.9% | 77.6% | 18.3% | 34.5% | 17.7 |
| 20.0% | 83.7% | 41.9% | 72.2% | 14.5% | 30.3% | 18.7 |

- 「地方」は 9 ブロック(北海道・東北・関東・中部・近畿・中国・四国・九州・沖縄)です。
- v0 の質問は大きな地域差だけを扱うので、セル(県内の地域)まではほとんど絞れません。これは想定どおりです。

## 質問データ

`data/questions/` に 1 問 1 ファイル(YAML)で置いています。

- 分布は「ゾーン(地方・都道府県・セルのリスト)ごとの回答分布+それ以外の既定分布」で書きます。セルを直接指定したゾーンは都道府県の指定より、都道府県の指定は地方の指定より優先されます。
- ビルド時にセル単位へ展開し、境界付近を平滑化します(セル代表点間の距離によるガウス重み、標準偏差 15 km。当初は 40 km でしたが、山梨のように大都市圏に隣接する県の特徴が周囲に埋もれたため、2026-11-19 に狭めました。`scripts/questions/expand.ts` の `QUESTION_BUILD_CONFIG` または質問ごとの `smoothing_km` で変更可)。
- どの回答にも 0.95 以上の確率は書けません(公開されている方言地図は高齢話者が中心で、若い世代とはずれがあるため)。
- 出典は実際に内容を確認できたものだけを書きます。確認できないものは「未確認」とし、`needs_review: true` にします。確信度 low も `needs_review: true` にします。これらはビルド時に検査されます。
- レビュー用の一覧は `docs/needs-review.md` に生成されます。

```
npm run questions  # src/generated/model.json、questions.json、docs/needs-review.md を生成
```

## 画面とログ

画面は、開始(同意事項)→ 質問(進行役・選択肢・ヒートマップ)→ 推定結果 → 正解入力 → 終了、およびクレジットです。

- **進行役**:最有力の地方ブロックの確率が 0.6 以上になると、その地方の方言で話します(`src/app/host.ts` の `HOST_CONFIG`)。台詞は `data/host/` に地方ごとに置いてあり、すべて `needs_review: true` です。
- **途中経過**:質問画面に、地方と都道府県それぞれの上位3つを%付きで表示します。
- **演出と音**:選択肢を押すと色が変わってから次へ進み、短い効果音が鳴ります。音は Web Audio で合成しているので音声ファイルはなく、右上のボタンで切れます。OS の「視差効果を減らす」設定では動きを止めます。
- **キャラクター**:進行役は `src/ui/face.ts` の SVG で、場面に応じて6種類の表情に変わります。
- **結果**:確信度に応じて、セル・都道府県・地方のいずれかの粒度で答えます。外れたら 2 番目、3 番目の候補で再挑戦し、最後に正解を選んでもらいます(都道府県とセルの選択式。「日本国外」「複数の地域で育った」も選べます)。
- **クレジット画面**:`LICENSES.md` と同じ元データ(`data/licenses.yaml`)から生成しています。
- **ログとコメント**:記録するのは質問 id・回答・最終推定・正解のセル id・任意のコメント(300字まで)・日付(日単位)だけで、開始画面で同意がなければ何も記録しません。コメント欄は、同意した人の正解入力画面にだけ出ます。`src/log/sink.ts` の `LogSink` に、何もしない `NoopSink`、開発時に localStorage へ保存する `LocalSink`、`site.config.json` の `logEndpoint` へ送る `HttpSink` があります。`logEndpoint` が空のあいだ、公開版は何も送信しません。送り先は Google Apps Script とスプレッドシートを想定していて、スクリプトと手順は `gas/` にあります(2026-11-19 にデプロイして動作を確認)。

## 構成

| 場所 | 内容 |
| --- | --- |
| `site.config.json` | リポジトリ名(Vite の base)、表示タイトル、記録の送り先(`logEndpoint`、空なら送信しない) |
| `gas/` | 回答とコメントを受け取る Google Apps Script と設定手順 |
| `data/licenses.yaml` | 権利情報の唯一の元データ。LICENSES.md とアプリ内クレジットの両方をここから生成する |
| `data/questions/` | 質問データ(1問1ファイル) |
| `docs/needs-review.md` | 質問データのレビュー一覧(生成物) |
| `data/host/` | 進行役の台詞(地方ブロックごと) |
| `scripts/` | データ加工・生成スクリプト |
| `scripts/import-gaj/` | 国語研データ取り込みの枠(未実装。データは同梱しない) |
| `src/engine/` | 推定エンジン(DOM 非依存) |
| `src/app/` `src/ui/` `src/log/` | ゲーム進行、画面、ログ |
| `tests/` | 単体テスト(vitest) |

## データを追加するときの決まり

- 配布ページを実際に開いて、ライセンス・クレジット表記・取得日を確認してから `data/licenses.yaml` に書く。記憶や推測で書かない。
- 確認できないデータは同梱しない。CC BY-NC など非営利限定のデータは使わない。
- npm パッケージも、依存に加える前にライセンスを確認する。
